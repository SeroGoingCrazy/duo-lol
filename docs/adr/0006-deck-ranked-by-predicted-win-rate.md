# 滑卡牌堆只按预测胜率排序，预测结果预先算好存起来

Tinder 早期用"受欢迎程度"给人打分排序，我们不这样做：排序依据必须能写成卡片上的理由（红线），而"被多少人喜欢"解释不了"一起能不能上分"。牌堆先按硬条件过滤（同意被推荐、按 `data/recommend.py` 的 `can_duo` 可双排、最近 14 天活跃、未拉黑、未滑过），再严格按预测胜率从高到低发牌，不混入探索卡。预测是逐对计算的，发牌时现算太慢，所以 worker 在会员注册或对局刷新后，把他和推荐池中候选人的预测连同理由和模型版本写进 `pair_predictions`。会员数 N 很大时 N² 对存不下，届时只为每人保留胜率最高的若干对；这个上限是存储取舍，不进入预测公式。
