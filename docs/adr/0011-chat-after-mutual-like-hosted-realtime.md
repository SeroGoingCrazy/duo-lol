# 互选后才能聊天；消息存在 app 库，用托管推送服务实时送达，推送不可用时退回轮询

v3 要做站内聊天（Jacky，2026-10-22）。聊天只对**互选**的两人开放：双向同意是陌生人敢用的前提，也让我们不必审核"陌生人第一条消息"这类最容易出骚扰的场景。消息属于会员数据，存在 `app` schema，由 Next.js 写（ADR-0004）。

实时送达的难点是部署：网站在 Vercel，函数不能长时间挂着 WebSocket。考虑过三种做法：在 Fly 上自己跑一个 WebSocket 服务（多一个要运维、要扩容的有状态服务）、纯轮询（最简单，但"正在输入"和秒级送达做不出来）、托管推送服务（Ably / Pusher，有免费档）。选托管推送服务，默认 Ably，但只把它当成"通知"：Next.js 先把消息写进 Postgres，再往对方的 `member:{id}` 频道发一个"有新消息"事件，客户端收到后从 Next.js 接口拉消息。所以推送服务里不存聊天内容，挂了也不丢消息，客户端自动退回轮询（对话打开时 5 秒，否则 30 秒）。客户端令牌由 Next.js 签发，只能订阅自己的频道，不能发布；"正在输入"也经由 Next.js 接口转发。

推送服务藏在 `web/lib/realtime.ts` 一个小接口后面（发布事件、签发令牌），换 Pusher 或自建只改这一个文件。本地开发和端到端测试不设 Key，就只走轮询，不依赖外部服务。代价是多一个外部依赖和一份 Key，以及免费档的连接数上限；超过时再评估付费或自建。
